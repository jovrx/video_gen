# 系统设置、客户端提交间隔与生成队列

## 目标与默认规则

新增独立系统设置入口，提供最大同时生成数（默认 3）和客户端提交间隔（默认 60 秒）。设置持久化到本机数据库，保存后立即生效。客户端默认指同一浏览器，多个标签页和刷新共用身份与提交时间。间隔到期允许提交下一条，不要求上一条已完成。

超过并发名额的任务仍被接收，进入先进先出的本地队列；返回任务 ID、当前排队号，并持续更新排队号。排队号从 1 开始表示当前等待顺序，与 RunningHub 平台排队状态分别显示。不估算无法可靠推断的生成完成时间。

## 实现方式与取舍

沿用 FastAPI、SQLite、单 worker 和现有 SSE，不增加 Redis 或独立队列服务。内存队列无法可靠恢复；额外队列服务增加现阶段不必要的部署依赖。数据库保存任务和客户端最近提交时间，进程中的调度器按数据库中的创建顺序启动任务。

增加系统设置的数据模型、存取接口和独立弹窗。只开放此次需要的两个参数，不将密钥暴露给前端，不加入无需求的其他系统参数。并发数为正整数，提交间隔为非负整数（0 表示关闭间隔限制）。

客户端身份由服务器 cookie 维持，不以 IP 合并同一网络中的不同用户。后端在受控事务中检查提交间隔并创建任务，避免同时请求绕过限制。失败的输入校验不消耗等待时间。429 响应包含剩余秒数及 Retry-After；前端倒计时并禁用按钮。页面恢复和其他标签页通过状态查询同步等待时间。

## 队列与恢复

新增本地等待状态。占用生成名额覆盖上传、平台提交、平台排队、运行和结果保存，避免目前仅在提交调用期间限流造成全系统生成数量失控。任务成功或已确认失败后启动队首任务；提高上限立即启动额外任务；降低上限保留已运行任务，待名额低于新上限后再启动。

启动时先恢复已有远程任务的监控，再安排尚未提交的队列任务。保留原任务 ID，任何恢复、关联 ID、下载重试都不重复创建远程视频。已完成生成的视频单独重试下载不重新占用生成名额。未配置 API Key 时保持队列等待，修改设置不会派发任务。对于提交结果未知的任务，需要保守保留名额，并提供人工核实后解除占用的入口，避免远程已创建但本地超时导致突破限制。

使用现有每秒检查的 SSE 更新排队号，分页记录和单任务查询也返回相同的队列信息。客户端只看到公开状态，不返回客户端标识、图片路径或工作流中的私有数据。

## 验证范围

使用模拟 RunningHub 验证默认 3 个完整生成任务占用名额，后续任务等待且按 FIFO 启动；任务完成和失败释放名额，设置动态升降即时生效，重启保持等待顺序并恢复已有远程任务。

验证同一客户端并发提交只接受允许的数量、等待结束后可再提交、不同客户端独立计时、非法素材不消耗间隔、刷新恢复倒计时。验证设置校验、持久化、排队号推进和 SSE 更新。运行现有测试、Python 静态检查与 JavaScript 语法检查，并在浏览器检查设置弹窗和队列状态。

## 影响范围

修改 app/config.py、app/store.py、app/jobs.py、app/main.py 和静态页面，按职责增加必要的小模块；增加设置、限流和队列行为测试，补充 README 中的使用说明。沿用仓库已明确的单 worker 部署范围。

## 用户确认

用户已确认本方案：按浏览器识别客户端、提交间隔默认 60 秒、同时生成数默认 3。
