# 剧本与分镜创作模块设计草案

状态：用户于 2026-10-12 确认，进入实现。

## 目标与操作流程

在现有 H3 视频工作台增加剧本创作入口。用户输入创意提示词，后端调用文本大模型生成剧本；用户编辑剧本后，指定分镜数量、每镜时长、目标视频模型及视觉风格，后端生成多个分镜。每个分镜的 Prompt 可以编辑、复制或一键填入现有视频生成表单。

首版中，“分镜”是文字分镜，不生成分镜图片。每个分镜对应一次可单独提交的视频创作。目标视频模型选项调整提示词写法；实际执行的视频模型由现有 RunningHub 工作流决定。

## 方案选择

推荐独立 OpenAI 兼容文本接口：统一调用 chat/completions，服务地址、API Key 和模型名可配置，适配用户已有服务。相比绑定单一服务商，更方便更换文本模型；相比加入复杂的多服务商 SDK 路由，首版依赖和配置更少。非兼容接口需要单独适配，不承诺仅填写地址即可使用。

另一方案是绑定具体服务商 SDK，适合用户明确指定专有接口的场景；第三种是把生成过程封装到新的 RunningHub 工作流，但它依赖额外工作流及输出解析，不适合作为本次默认方案。

## 界面

- 在左侧创建视频栏增加“剧本与分镜”入口，打开宽屏创作弹窗；沿用 PC 优先布局和中英界面切换。
- 第一步：创意输入、生成剧本按钮、可编辑剧本文本。剧本包含标题、角色、场景、动作和对白，正文按用户输入语言生成。
- 第二步：使用当前编辑后的剧本，设置分镜数量（1–24，默认 6）、每镜时长（整数秒，默认 8）、目标模型（H3、通用、自定义）和可选视觉风格。自定义目标模型允许填写名称及格式要求。
- 每个分镜显示序号、标题、时长、画面/动作、景别与运镜、对白/声音、可编辑 Prompt，以及“复制 Prompt”“用于视频生成”。所有文字字段均可编辑。
- 浏览器保存当前创作草稿及编辑后的分镜，关闭弹窗和刷新后可继续；提供明确的清空草稿操作。首版不建立服务端剧本历史库。
- LLM 配置状态独立显示；即使 RunningHub 尚未配置，仍可使用剧本和分镜功能。

## 文本模型配置

配置沿用仓库现有 .env 模式，增加 LLM_BASE_URL、LLM_API_KEY、LLM_MODEL 和 LLM_TIMEOUT_SECONDS。地址定义为 API 根地址，例如 https://api.openai.com/v1；请求追加 /chat/completions。模型名需用户明确填写，API Key 与 RunningHub Key 独立。

服务端仅向浏览器返回是否配置、文本模型名、目标 Prompt 格式列表，不返回密钥。缺少配置时给出变量名和重启说明，用户输入的创意和剧本仍可保存。

## 后端职责与接口

- 新增 app/llm.py：异步 HTTP 调用、超时及服务商错误处理、输出解析；复用 httpx。关闭应用时释放连接，不自动重试付费请求。
- 新增 app/storyboard.py：请求/结果 Pydantic 模型、剧本与分镜生成指令、目标模型 Prompt 格式规则、结果校验及路由。通过 router 接入 create_app，避免继续扩大主路由文件。
- GET /api/creation/config：配置状态、文本模型名及可用 Prompt 格式。
- POST /api/creation/script：JSON prompt（去空白后 1–20000 字符），返回 title 与 content。content 是可编辑完整剧本，最大 40000 字符。
- POST /api/creation/storyboard：JSON script、shot_count、duration、target_model、custom_model、visual_style；返回 shots 数组。每项包含 number、title、duration、visual、camera、audio、prompt。custom_model 在选择自定义时必填。
- 分镜数必须等于请求数量；序号连续；每镜时长必须等于请求值；关键字段不允许空字符串；单个 Prompt 最多 20000 字符，以匹配现有视频表单。
- 提示模型输出 JSON，兼容纯 JSON 和外层 Markdown JSON 代码块；不依赖所有服务商都支持 response_format。无法解析、内容截断或结构不符时返回清晰错误，不展示伪造结果。

## Prompt 规则

通用格式按主体、环境、动作、景别、运镜、光照、风格和声音组织，保留角色及服饰的一致性；每镜写出完整可独立使用的描述。

H3 使用 h3-prompt-writing 的格式要求：具体视听动作及准确的镜内时间线，英文描述，对白保留原语言。没有输入参考素材信息时使用基础文本格式，不凭空建立 Picture/Video/Audio 引用。有参考图绑定需求时，用户可在编辑 Prompt 时注明其对应关系，上传图仍通过现有视频表单完成。

自定义模式将目标模型名和格式要求交给文本模型作为生成约束。视觉风格单独填写，例如写实电影、动画或广告，不与服务商、文本模型和目标视频模型混淆。

## 与现有视频流程衔接

点击“用于视频生成”将该分镜当前编辑后的 Prompt 写入 #prompt，触发既有 input 更新字数和提交状态，并定位到创建视频栏。镜头时长仅在当前工作流支持范围内同步；超出范围时保留当前视频时长并显示需要调整的提示，不静默截断。

操作仅填入文字和可兼容的时长，用户随后添加/确认参考图并点击“生成视频”。视频任务继续使用已有工作流、持久队列、进度和结果管理机制。

## 错误与交互状态

生成期间禁用对应生成按钮，避免重复点击；同时阻止生成结果覆盖正在编辑的内容。成功后更新对应区域，失败时保留已有剧本、分镜及输入。超时、认证失败、限流、上游不可用、空内容及格式错误使用独立友好提示，不返回上游原始响应或密钥。

草稿存储不可用时仍可正常编辑和生成，并提示刷新后不会保存。模型输出作为普通文本显示，不作为 HTML 执行。切换界面语言不翻译或清空创作内容。

## 验收与验证

1. 使用模拟 LLM HTTP 响应验证剧本生成、用户修改剧本后生成指定数量分镜，以及配置地址、模型名和认证头正确传递。
2. 校验未配置、空输入、超范围数量/时长、超时、认证失败、限流、非 JSON、截断、错误分镜数和字段缺失等情况；确保错误不泄露 Key。
3. 验证 H3/通用/自定义约束及视觉风格传入文本模型；输出校验不允许无效分镜直接进入界面。
4. 浏览器验证编辑、草稿刷新恢复、复制、填入提示词和字数更新、时长兼容提示，以及中英切换后的内容保持。
5. 检查 PC 弹窗布局和已有视频生成流程，执行 Python 测试、相关 JS 验证、Ruff 和 git diff --check。
6. 真实服务商调用需要有效 LLM 配置；配置未提供时，通过模拟接口验收并明确记录真实接口尚未验证。
